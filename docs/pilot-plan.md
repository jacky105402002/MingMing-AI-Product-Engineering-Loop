# 真實產品試跑與成效驗證

狀態：待選定真實產品與功能。本 repo 自身的維護／驗證可檢查模板與工具，不能替代含 UI、API、DB 的端到端產品試跑。

## 第一輪

選一個有明確 AC、可在測試環境操作的功能，包含 UI／API／資料變更與一個重要未知。先查證：若未知有來源就自行解決，若必須由產品負責者決定才問。
AI 自主完成設計、Node、實作、測試、修正、review、文件與已授權發布驗證。實際平台要求核准時照規則辦理。

## 記錄

| 指標 | 定義／來源 |
|---|---|
| 不必要詢問 | 已有可取得答案、同範圍已授權，仍要求人重複回答的次數 |
| 關鍵漏問 | 缺口導致錯誤產品行為，直到 review／使用者驗收才發現的次數 |
| 完成可靠度 | done Nodes 中，抽查 AC 與證據一致的比例；記分子與分母 |
| 返工 | 每 Node 修正次數及根因，區分測試發現與發布後漏出 |
| 成本／時間 | 平台實際 token、費用與 elapsed；取不到填 unknown，不估成零 |
| 成效 | feature-spec 的預期結果、量測來源、基準、發布後觀察時間與負責者 |

首輪先建立基準，不宣稱固定 token 節省比例。由試跑結果調整路由、詢問閾值與 context，不以降低問題數犧牲正確性。
發布後觀察由實際排程或再次執行取得；本模板不會自行啟動背景監控。
