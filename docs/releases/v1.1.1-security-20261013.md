# MingMing v1.1.1 — 資安規劃更新

工作流版本為 **1.1.1**。本次修訂標籤為 `v1.1.1-security-20261013`，用於識別 2026-10-13 的新增內容；原 v1.1.1 標籤及其下載檔保留。

## 新增能力

- 新增第 12 個角色 security-planner。政府標案確認為是時啟動，等級未知先盤點；確認高／中／普後建立對應要求。
- 內建 62 項候選摘要：27 項防護基準、8 款委外要求、27 項年度聯合稽核項目。逐案核對來源版本、契約與適用性，非全部一律必交。
- 要求串連設計、開發 Node、驗證方式、證據及匯入表單；草稿、規劃、交付分別檢查。
- 證據與程式／設定輸入保存 SHA-256，變動後須重驗。無證據或過期不能標示符合。
- 支援 CSV 映射回填副本；Word／Excel／PDF 另依文件工具保持原格式與版面，簽章及必要獨立第三方檢測由實際負責者完成。
- 保留四項精選 React 資源與原有自治開發流程。

## 導入

依 [導入指南](../adoption.md)比較及合併，保留原專案規範與進行中任務。更新驗證器時須一併複製 `.agents/skills/security-planner` 完整目錄。詳見 [資安規劃師](../../.agents/skills/security-planner/SKILL.md)。

新 active 任務記錄 feature.security；舊狀態仍可讀取，但缺欄位不表示已確認非政府標案。一般開發也可獨立使用此 Skill。個人 Codex 的全域分流須在該電腦安裝／設定，不會因下載本 repo 自動修改其他電腦。

## 驗證與限制

Node.js 22+，無第三方執行依賴。`node scripts/check.mjs` 檢查文件及 61 項工具測試；另驗證 `tasks/validation/security-planner/state.json` 的有效證據。審查為 self-review，未宣稱獨立審查。CI 與發布結果以該修訂的 GitHub Actions／Release 為準。

真實標案契約與正式 Word／Excel／PDF 表單尚待首案驗證；本次 CSV 使用合成測試資料。來源摘要不是法律原文或合規認證，仍須逐款覆核個案適用性、正式檢測及機關驗收。工程會契約附件列為個案待確認來源。其他限制見 [known issues](../known-issues.md)。
