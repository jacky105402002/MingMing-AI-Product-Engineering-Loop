# 流程與架構圖規範

## 選擇與責任

需要多角色／多分支流程、跨系統架構、後續人工編輯或正式圖檔交接時，優先使用可用的 Next AI Draw.io MCP。短小且文字已清楚的說明可用 Mermaid 或文字；已有可用圖先接續，不為換工具重畫。使用者指定的格式優先。缺少 Draw.io 不自行安裝、改設定或假裝完成匯出；非必要圖可採等價方式，必交可編輯圖則記錄受阻部分。

| 主責 | 圖表與必要內容 |
|---|---|
| flow-designer | 業務／泳道／狀態圖：觸發、角色、條件、正常／例外結果、重試與恢復；對應 AC |
| system-architect | 系統邊界／模組／部署圖：元件責任、連線方向、外部依賴與資料流；對應決策及實作來源 |
| security-planner | 提供適用控制、敏感資料及信任邊界，與架構師共用圖；圖不是控制措施已符合的證據 |
| data-modeler | 必要資料關聯圖；以既有 schema／migration 為準，記錄版本，不複製另一份資料定義 |
| uiux-designer | 頁面導覽與使用者流程；已選 Ming-design loop 時接回其交接，不替代精緻介面與互動規格 |
| docs-maintainer | 保存主檔、逐頁預覽、來源、修訂及驗證結果；主線唯一維護任務狀態 |

## 先定義內容再繪圖

先讀需求、AC、現有程式／部署資料、ADR 與既有圖。每張圖記用途、範圍、來源版本和主責，區分「現況」「規劃」「待確認」。沒有事實來源不能把常見架構元件畫成已實作；重要業務條件不明先查證，無法確認才詢問，其他不依賴部分繼續。

沿用專案元件／流程 ID。以圖表 ID、page ID、cell ID 或穩定標籤連到 AC、ADR、API、資料定義及適用資安要求；不為填表虛構 Node。尚未拆 Node 時先對照 AC，拆分後補主線關聯。文字規格管理業務語意，圖提供視覺對照；兩者衝突先查來源，不自行讓圖取代規格。

## 操作、保存與人工接續

操作細節見 [Draw.io 操作](../docs/drawio.md)，參數以當前工具 schema 為準。

1. 確認實際工具、版本、圖表與寫入範圍；本機有 drawio-local 時按需讀取並檢查，其他環境不用套本機路徑。
2. 新圖開新 session；接續圖先確認最新檔案／畫布及編輯者。讀取 get_diagram 後以 edit_diagram 增量修改，保留未涉及的 ID、文字與排版。
3. 只有明確要建立全新內容才用 create_new_diagram；它會取代全部頁面。新增分頁用 add_page；載入既有檔前保存目前需保留內容。雲端／專用圖示先查 get_shape_library，不猜圖示名稱。
4. 人工修改後先讀回；同張圖一次一個寫入者。遇到並行修改拒絕，重新讀取並合併，不能用舊圖覆蓋。Desktop 與 MCP 不自動同步，靠最新已保存主檔明確交接。
5. 正式 Draw.io 交付保存完整 .drawio 主檔，並為交付範圍內每頁輸出 PNG（或使用者指定 SVG）。逐頁明確指定 page ID／index；不把作用中頁面當整份文件。一般 SVG 不保證保留可編輯資料。
6. 查核檔案存在、非空、預覽可讀；用新工作階段載入匯出的主檔並讀回，核對頁面、關鍵文字／連線及 ID。目視檢查換行、遮擋、箭頭與圖例；修正後重新匯出及核對。

正式檔案保存於專案既有成果目錄；沒有慣例可用 docs/diagrams/。session URL／autosave 只供當次操作與恢復，不是正式來源。session URL 可能帶存取資訊，不放公開 repo；跨聊天優先交付主檔位置、revision、最新內容位置、待辦及原編輯者是否已停止，必要 session 資訊只留在允許的本機交接。

## 驗收與證據

使用 [圖表交接模板](../tasks/templates/diagram-handoff.md) 或專案等價格式。主檔、實際預覽及交接文件列入受影響 Node 的 evidence_files，按既有 recorder 保存真實 test／review／docs 證據。沒有新增 state JSON 欄位，也沒有背景自動同步。

- 內容：流程分支有條件與出口，異常及恢復與來源一致；架構邊界、元件責任、連線方向及現況／規劃標示清楚。
- 操作：讀回、增量修改、完整匯出、重新載入及目視結果分別記錄；未執行就寫未驗證，不能由工具回報成功推論全數通過。
- 交付：各頁可辨識且有預覽；來源及 AC／決策／元件對照可查，既有人工修改保留。
- 變更：需求、圖表或實作變動，分析受影響 Node，重新建立適用 revision／attempt 與證據。雜湊能發現檔案變動，不能證明圖與系統語意一致；review 必須實際核對。

圖表 ready 只表示該設計範圍可用，不等於整體 Implementation Ready、程式測試通過或資安驗收。圖為可選說明時不強制要求所有產品產圖；已約定的必要圖或預覽缺失，則保留明確阻礙，其他無依賴工作繼續。
